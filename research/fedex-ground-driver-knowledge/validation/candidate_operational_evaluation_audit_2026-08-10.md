# Candidate operational evaluation audit

Status date: 2026-08-10

## Purpose and design

Sixty-nine development prompts from the owner-supplied candidate pack were independently mapped to canonical Ready Route operational records. Candidate expected answers were not used as authority. Every gold case carries canonical knowledge IDs, information sufficiency, response mode, required clarification, prohibited behavior, and source candidate trace.

The evaluated prompts are not added to `driver_question_variants`, the formal 192-case retrieval index, or any record pattern. The baseline therefore measures generalization from the maintained knowledge surfaces rather than exact-prompt memorization. All 32 deterministic holdout prompts remain untouched.

## Baseline result

| Measure | Result |
| --- | ---: |
| Reviewed development cases | 69 |
| Top-1 canonical match | 44 |
| Top-5 canonical match | 56 |
| Production response-mode match | 49 |
| Correct publication-withheld escalations | 10 |
| Unsafe answer-gating failures | 0 |
| Retrieval failures | 13 |
| Response-mode failures | 20 |

The exact deterministic result is preserved in `validation/candidate_operational_retrieval_results.json` and regenerated by `npm --prefix backend run knowledge:validate-candidate-retrieval`.

## Failure profile

The 13 top-five retrieval failures cluster around active-threat versus accident reporting, generic signature language versus hazmat signature, leak/damage language, pickup-ready state, generic release requests, mailbox placement, FORGE login/sync, ID-controlled delivery, and roadway obstruction. The 20 response-mode failures include premature answers, unnecessary clarification for verified term definitions, clarification-versus-escalation mistakes, and misses caused by selecting the wrong record. The exact case-by-case rows are preserved in `validation/candidate_operational_retrieval_results.json`.

These are retrieval, classification, or response-mode failures, not permission to weaken gold expectations. Do not add the exact prompts as synonyms merely to make the score green.

The first expanded run also exposed one unsafe answer-gating failure: `business closed can i leave it` selected the eligible administrative closure-message workflow even though the package-release procedure is not production eligible. The decision layer now explicitly prevents a closure message from becoming package-disposition authority. The expanded suite and the maintained 192-case suite both pass with zero unsafe answer-gating failures after that fix.

## Status-gating result

Ten publication-withheld cases escalated because at least one controlling expected record is not production eligible. No candidate prompt now causes a definitive answer from non-eligible knowledge. This is the most important current safety result, but it does not excuse the retrieval or clarification defects.

## Next action

All development prompts are now classified; preserve the holdout. Before further retrieval-layer remediation, classify each failure as taxonomy, query interpretation, candidate scoring, decision-pattern, or response-mode logic. Fix the underlying layer without weakening canonical status gates and then rerun both the maintained 192-case suite and this unseen-development suite.
