# Candidate operational evaluation audit

Status date: 2026-08-10

## Purpose and design

Thirty-three development prompts from the owner-supplied candidate pack were independently mapped to canonical Ready Route operational records. Candidate expected answers were not used as authority. Every gold case carries canonical knowledge IDs, information sufficiency, response mode, required clarification, prohibited behavior, and source candidate trace.

The evaluated prompts are not added to `driver_question_variants`, the formal 192-case retrieval index, or any record pattern. The baseline therefore measures generalization from the maintained knowledge surfaces rather than exact-prompt memorization. All 32 deterministic holdout prompts remain untouched.

## Baseline result

| Measure | Result |
| --- | ---: |
| Reviewed development cases | 33 |
| Top-1 canonical match | 28 |
| Top-5 canonical match | 29 |
| Production response-mode match | 28 |
| Correct publication-withheld escalations | 3 |
| Unsafe answer-gating failures | 0 |
| Retrieval failures | 4 |
| Response-mode failures | 5 |

The exact deterministic result is preserved in `validation/candidate_operational_retrieval_results.json` and regenerated by `npm --prefix backend run knowledge:validate-candidate-retrieval`.

## Retrieval failures

1. `guy threatening me` retrieves accident reporting instead of active-threat/security-incident knowledge.
2. `needs sig no one there` retrieves the hazmat-signature branch instead of the ISR/DSR/ASR signature family.
3. `package fell and leaked` retrieves package notation instead of leak safety plus damage inspection.
4. `pickup not ready` retrieves unlisted pickup instead of distinguishing ordinary zero-package from call-tag-not-ready.

These are retrieval/classification failures, not knowledge-status failures. Do not patch the expected answers or add the exact prompts as synonyms merely to make the score green.

## Response-mode failures

`do i need a picture for this one` answers before establishing the PPOD branch. Four direct terminology questions—`what is fad`, `what is hal`, `what is ppod`, and `what is sra`—retrieve the correct record but ask unnecessary clarification instead of giving the verified definition and critical boundary.

## Status-gating result

The tobacco, residential-vaping, and stolen-vehicle prompts all escalated because their canonical records are `PENDING_REVIEW`. No candidate prompt caused a definitive answer from non-eligible knowledge. This is the most important current safety result, but it does not excuse the retrieval or clarification defects.

## Next action

Continue gold mapping on development prompts and preserve the holdout. Before any retrieval-layer remediation, classify each failure as taxonomy, query interpretation, candidate scoring, decision-pattern, or response-mode logic. Fix the underlying layer without weakening canonical status gates and then rerun both the maintained 192-case suite and this unseen-development suite.
